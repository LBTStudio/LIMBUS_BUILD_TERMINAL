# インライン効果リファレンス（2026-10-23）

## 目的

人格パッシブ／スキル／ダイス、E.G.Oのパッシブ・覚醒／侵蝕・固有効果、アイテム、カスタムスキルの効果文に現れる用語・固有名詞について、別画面へ移動せず本文の近くから詳細を確認できるようにする。サポートパッシブは対象外とする。

## 挙動

- PC：用語上にマウスを置くと短い遅延後にポップオーバーを表示。クリックでも開閉でき、キーボードフォーカスとEscによる閉じ操作をサポート。
- スマートフォン／タッチ：タップで開閉し、約480msの長押しでも表示。
- 表示位置はアンカー要素の位置とビューポートから決め、画面端で左右・上下に収める。ポップオーバー本文だけをスクロールできる。
- ポップオーバーのテキストはReactの通常テキストとして描画し、HTML文字列として挿入しない。

## 参照データと誤説明の回避

1. 共通用語辞典は基本ルールに加え、特定抽出パック第一弾 p.196–217 の追加バフ・デバフ・中立バフ・弾丸・特殊処理を収録する。蓄積要素・特殊資源も独立した分類で扱い、角括弧なしの本文から照合して出典ページと説明を表示する。
2. 人格の固有バフは `data/db.json` の `unique_buffs`（名前・種別・初期値・最大値・説明）を参照する。
3. E.G.O固有効果は `unique_buff` の記述と、E.G.O名／ランクを出典として表示する。
4. サポートパッシブ・死亡後サポートパッシブはホバー対象外。通常の固有語照合は現在表示中の所有者レコード内に定義があるものだけを使う。
5. 人格・E.G.Oの固有名詞は、通常本文では同一所有者の定義だけを参照する。別人格の固有語を引用する場合は、角括弧内の完全一致に限って参照できる。参照先が複数人格に存在する同名語は曖昧としてホバーを出さない。複合語の一部一致は引用として扱わない。同期・カスタムデータは表示元レコードを優先し、古いDB定義へフォールバックしない。
6. 検索対象を表示時に文字列分割するだけで、原文やDBは書き換えない。入力フォームは対象外。

## 文脈混入への追加制約（2026-10-30）

- サポートパッシブの名前・効果文はインライン用語辞書へ登録しない。サポートパッシブ本文のレンダリングもホバー化しない。
- 通常本文で別人格の固有効果へ自動移動しない。角括弧内の完全一致引用のみ例外とし、同名所有者が複数なら解決しない。偶然の部分一致（例：「集中攻撃」の「集中」）は引き続き禁止する。
- 文脈で説明を解決できない文字列はホバーを付けず、元の本文をそのまま表示する。


## 所有者スコープの原則（2026-10-30 更新）

- 通常の検索対象は「共通用語辞典」と「現在表示中の所有者の定義」に限定する。
- 他人格のパッシブ名・固有バフは通常本文の候補に混ぜない。角括弧で固有語を完全一致引用した場合だけ、引用元が一意に特定できる定義を参照する。
- 抽出パック第一弾の追加用語（p.196–217）を共有辞典に収録し、バフ・デバフ・中立バフ・蓄積要素・弾丸・特殊処理を区別する。
- 同期／カスタム人格は現在のレコードを渡して索引化する。固有名詞が通常の文章中に書かれていても、同じ人格の定義と一致すればホバーできる。
- サポートパッシブと死亡後サポートパッシブはホバー対象外。
- 「針」「杭」「傷」のような単一文字の一般語は平文の誤一致を避けるため通常照合から除外し、角括弧で明示された場合だけ共有辞典へ接続する。
- 共通辞典にはバフ／デバフだけでなく、煙・バリア・挑発値・電圧・蓄積要素・弾丸・爆発なども含める。
