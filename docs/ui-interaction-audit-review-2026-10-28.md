# UI操作経路監査と改善案 — 2026-10-28

## 監査範囲

Playwright／Chromiumの使い捨てブラウザーで、1440×1000のデスクトップと390×844・タッチ有効のスマートフォン想定画面を採取しました。前回の監査セットは94枚（デスクトップ50枚、モバイル44枚）で、通常画面のほか、ビルド内の各タブ、ショップ分類、記録の取り込み、使い方検索、クイック検索、操作・保存、アカウント管理、読み込み確認、ホバー／フォーカスを含みます。

これは実機iOS／Android・物理キーボード・スクリーンリーダーを完全に代替するものではありません。監査用に生成したデータはテストブラウザー内だけで、読み込み確定は行いません。

## 確認した問題と修正

### P1 — ビルド／記録タブがスマホで横に隠れる

横スクロール型のタブ列では後半のタブが見切れ、横スワイプできることも自明ではありません。ビルドは8項目、記録は複数のタブがあり、未発見機能が出る原因になります。

**対応:** 640px以下では4列のグリッドに切り替えて複数行に収めます。ショップ6分類は3列、下部ナビは4列×2行にし、項目が端に孤立しないようにします。

### P1 — プレビュー開閉ボタンが見出しと操作列を覆う／二重に存在する

LivePreviewのエッジ切替とApp側の古いPREVIEWタブが同時に存在し、右端の領域を見づらくします。

**対応:** 古いPREVIEWタブを格納状態では隠し、LivePreview側のコントロールを唯一の操作にします。スマホでは横長のボタンとして下部ナビの安全領域の上へ移し、見出し・タブと干渉しない配置にします。

### P2 — 英日併記見出しの末尾一文字が孤立する

英語タイトルと日本語タイトルを一つの文字列で折り返すため、狭い幅で日本語の最後の一字だけが次行に残る状態を確認しました。

**対応:** 英語／日本語タイトルを別spanにして、日本語部分を分割しないようにします。小画面では見出しの字間・文字サイズを抑え、補助文を次行へ送ります。

### P1 — 読み込み確認ダイアログの選択肢と確定ボタンが縦に伸びる

小さな画面に、データが存在しないカテゴリまで同じ見た目で並べると、今回必要な選択肢が見つけづらくなります。フッターが押し出される危険もあります。

**対応:** データがあるカテゴリだけを先に表示し、空のカテゴリは展開式に分離します。ダイアログを高さ制限付きの列レイアウトにし、選択肢だけをスクロール、確定・キャンセルボタンは下部に残します。Esc、初期フォーカス、Tab循環も追加します。

### P1 — 記録の取り込みボタンを押しても追加パネルが見える場所へ移動しない

リザルト記録の下にテキスト／硝子窓／所持人格リストの入力欄が展開されるため、クリック後に表示位置が変わらず、反応しなかったように感じます。

**対応:** 対応する取り込みパネルへスクロールし、最初の入力欄へフォーカスします。prefers-reduced-motionを尊重し、開くだけでインポート確定はしません。

### P2 — アカウント編集で共有URL取り込みが背後のカードと競合する

長い取り込みフォームの後ろにアカウントカードや任意のオンライン保全パネルが残り、情報が密集します。

**対応:** 共有URL取り込み中は編集対象のカードを優先し、他カードとオンライン保全パネルを一時退避します。終了・キャンセル後には一覧に戻れる状態を維持します。

## 検証の扱い
