# UI操作経路監査レビュー — 2026-10-28

## 監査方法と範囲

Playwright／Chromiumで、デスクトップ（1440×1000）とタッチ有効のスマートフォン想定（390×844、DPR 2）を走査する。撮影はアプリをローカルHTTPで起動し、一時ブラウザープロファイルと合成の監査データを使う。操作の入口、ダイアログ、展開後のパネル、主要タブ、ホバー、キーボードフォーカスを撮り、コンソール／HTTPエラー、横はみ出し、重要コントロールの到達性を manifest に記録する。

本確認は実機iOS／Android、OSソフトキーボード、スクリーンリーダーを完全に代替しない。共有URLやバックアップの取り込みは確認画面までで、適用を確定しない。

## 確認できた問題と今回の対応

### P1 — スマートフォンのプレビュー展開タブが見出し／コンテンツに重なる

既存の LivePreview 開閉タブに加えて App が旧 `.preview-reopen` ボタンも描画し、CSSの詳細度により格納状態で旧ボタンが再表示されていた。タブ列や本文の右端に重なり、背後の内容を隠す。

**対応：** 旧再表示ボタンを格納状態でも非表示にし、LivePreview側の開閉タブだけを残す。スマートフォンでは縦長タブを下部ナビより上の小型水平ピルへ移す。

### P1 — ビルド／記録のタブ列が横方向に隠れる

390px幅ではビルド8タブと記録タブの後半が横スクロール領域に入り、存在する機能を見つけにくい。

**対応：** 640px以下ではビルドと記録のタブを4列グリッドにして全候補を表示する。ショップの6分類も3列×2段、下部ナビも4列×2段として孤立した「その他」の段をなくす。

### P1 — セーブデータ読み込み確認が長く、空カテゴリが視覚ノイズになる

前回の画面では空データのカテゴリが全て並び、スマートフォンの下端で操作ボタンが隠れていた。

**対応：** データを含むカテゴリのみを初期表示し、空カテゴリは折りたたみへ分離。選択肢リストだけを内部スクロールにし、適用範囲と確定／キャンセルを見える領域に固定。dialogのARIA、初期フォーカス、Tab循環、Escape終了も追加する。

### P1 — 初回アカウント作成フォームの操作ボタンがカード下端に隠れる

監査ブラウザーの新規プロファイルで「新しいキャラクター」を押すと、フォームが狭い自動グリッド列に置かれ、アイコン行と「作成して開く」操作が表示領域から押し出されるように見えた。初回設定を完了できない可能性があるため、独立した再現テストと同時に修正する。

**対応：** 初回作成フォームが開いている間は、カード一覧を1列のスクロール領域に切り替え、フォームを全幅にする。任意のオンライン保全パネルを一時的に隠して作成操作に領域を割り当てる。撮影スクリプトは実際のフォーム操作ボタンをクリックし、ゲートが閉じることまで確認する。

### P1 — 記録の取り込みを開始しても入力先が画面外に残る

「記録 → リザルトを記録 → 取り込む」から文章／硝子窓／所持人格リストを開くと、新しいパネルが文書下方に追加されても表示位置が移らず、押しても反応がないように感じる。

**対応：** 開いたパネルへスクロールし、最初の入力欄へフォーカスする。動きは `prefers-reduced-motion` を尊重し、開いただけで反映を確定しない。

### P1 — 共有URL取り込みと背後のアカウントカード／オンライン保全パネルが重なる

共有URL取り込みフォームが長い状態でも、背景側の「新しいアカウント」カードと任意のオンライン保全パネルが同時に見え、フォームの説明や入力領域が圧迫される。

**対応：** 取り込み中はカード群を1列のスクロール領域にし、編集中のカード以外とオンライン保全パネルを一時的に隠す。終了／キャンセルで通常の一覧へ戻す。カードの更新日時と常時表示の編集操作も離して配置する。

### P2 — 英日併記見出しの日本語末尾が一文字だけ次行に落ちる

「OWNED PERSONAS / 所持人格」などの見出しで日本語末尾が孤立し、見出しが読みづらい。

**対応：** 英語部分と日本語部分を別のspanにし、日本語側は分割しない。狭い画面では文字サイズ、行間、補助文の幅を調整する。

## 撮影側の誤判定への対策

- `display:none` だけでなく、opacityと `aria-hidden` も考慮して可視要素を判定する。
- ダイアログ撮影後は明示的な閉じる操作を試し、前のモーダルが残った状態で後続画面を撮らない。
- 任意のCloudflare RUMビーコンはローカルの静的サーバでは処理できないため、`/cdn-cgi/rum` を204で受け、無関係な404を監査失敗に混ぜない。
- 必須画面の欠落、スクリーンショット失敗、コンソール／HTTPエラー、重要な重なりはジョブ失敗として記録する。

## 検証の限界

CIのスクリーンショットはブラウザーレイアウトの再現であり、実機確認ではない。幅・高さ・タブ操作・モーダル内容は自動検査するが、実際の利用者がすべてのデータ分岐をどう理解するかは、画像の目視レビューも必要。
