# 抽選の複数回費用プレビュー監査（2026-10-23）

## 発見した不具合

人格をまだ1件も所持していない状態で、ショップの抽選回数を2回以上にすると、確認画面の合計費用が実際より少なく表示される。

画面側は `paidCost("persona", state)` で1回分の単価を取得し、その単価を回数へ掛けていた。未所持の初回は無料なので単価は0LPとなり、「初回無料、2回目以降100LP」という価格段階を合計へ反映できていなかった。

一方、抽選エンジンの `drawBatch` はバッチ内の抽選ごとに所持数を進めて費用を算出する。そのため、3回抽選の画面表示は無料でも、実際の取引は200LPになるケースが生じる。残高不足の事前判定も同じ合計額を使うため、誤った費用表示だけでなく、実行可否の判断も一致しない。

## 修正内容

- `js/gacha-tickets.js` に `estimateTotalCost` を追加。人格抽選はエンジンの `RULES.personaDraw` を参照し、希望回数ぶん所持数を逐次増やして合計費用を計算する。
- E.G.O抽選とテーマパックは既存のルール値・パック価格から回数分を積算する。
- `js/OtherSections.js` の抽選確認UIと残高不足判定は、同じ見積もり関数を使用する。
- `tests/gacha-cost-preview.test.mjs` で未所持の1／2／3回、既所持、特異人格が先に所持されているケース、E.G.O／パック費用、回数上限、UI連携を検証する。
- `index.html` のアセット参照と `sw.js` のプリキャッシュを再同期する。

## 監査の結論と制限

この修正は「表示上の費用」と「抽選エンジンが使う価格段階」の不一致を解消するもの。実ブラウザーでの操作、スマートフォン表示、オンライン／オフライン切替の実機E2E検証までは代替しない。抽選証明の公平性保証に関する別問題も対象外。
