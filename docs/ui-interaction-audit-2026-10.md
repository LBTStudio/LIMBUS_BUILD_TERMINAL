# UI操作経路・細部画面の監査 — 2026-10

## 対象と方法

Playwright + Chromium で実際のアプリを開き、デスクトップ（1440×1000 CSS px）とスマートフォン想定（390×844 CSS px、タッチ有効）の2条件で合計94枚を採取した。初回アカウント選択／作成、ビルド8タブ、人格カード選択・人格テキスト取り込み、駒整形、ショップ6分類、記録の取り込み、使い方検索、クイック検索、上部ボタンと操作・保存シートのホバー、免責事項、アカウント管理・編集・共有URL取り込み、保存データ読み込み確認、キーボードフォーカスを含む。

- 画面エラー：JavaScript の pageerror は0件。
- ページ全体の横はみ出し：0件。
- ローカル静的サーバーが Cloudflare の計測エンドポイント /cdn-cgi/rum に404を返した記録が4件。ローカル撮影環境固有のもので、アプリ本体のJavaScript例外とは区別する。
- スマートフォンは Chromium のエミュレーションであり、実機のSafari／Chrome、ソフトウェアキーボード、端末ごとの安全領域までは検証していない。

## 目視レビューで確認した問題と修正

### P1 — モバイルのプレビュー開閉タブが本文を覆う

**観測:** 右端に固定された縦長の「展開」タブが、セクション見出しとビルド内のタブ帯に重なっていた。見出しには右側48pxの予約余白もあり、英日併記の見出しが日本語1文字だけの行を作ることがある。

**対応:** 640px以下では開閉操作を横向きのピルボタンとして下部ナビの上へ移動。見出しの予約余白を外し、見出しは text-wrap: balance で行を整える。閉じたときの表示名も「展開」から「プレビュー」へ変更する。

### P1 — ビルドの8タブの一部が見切れる

**観測:** タブ列は横スクロールできる一方、表示端に隠れたタブがあり、スクロール可能なことを示す明確な手がかりがない。

**対応:** スマートフォンでは4列×2行のグリッドへ変更し、8タブを初期表示に収める。各タブの最小高さを44pxにし、長いラベルは折り返して表示する。デスクトップは従来の横並びを維持する。

### P1 — 保存データ読み込み確認が長く、空カテゴリの比率が高い

**観測:** データが存在しないカテゴリも同じ一覧に並び、少数カテゴリだけを読み込みたい場合でも無効な行が大量に見えていた。操作ボタンも内容と一緒に縦スクロールする構造だった。

**対応:**
- 初期状態はファイルにデータがあるカテゴリだけを表示。
- 「データがない項目も表示」で全カテゴリを確認できる従来の自由度を残す。
- 一覧部分だけをスクロールさせ、操作列をダイアログ下端に固定。
- 画面高に合わせた最大高さを設け、スマートフォンは下寄せのシート風レイアウトにする。
- role=dialog、aria-modal、読み上げ用タイトル、Escapeで閉じる動作、Tab／Shift+Tabのフォーカス循環、閉じた後のフォーカス復帰を追加。

## 追加で継続監視する項目

1. スマートフォン実機で、下部ナビ・安全領域・ソフトウェアキーボードが表示された状態を再確認する。
2. 320px幅と200%ズーム相当で、ヘッダー・ショップ分類・記録一覧・長い名称の折り返しを確認する。
3. 各取り込みダイアログで、成功／エラー／キャンセル後にフォーカスが自然な位置へ戻るか、Escで閉じても入力データが適用されないことを確認する。
4. ホバーのないタッチ端末で、ツールチップにしか存在しない重要情報がないかを追加監査する。今回、PC用ホバー状態は採取したが、全ボタンのツールチップと全ての状態遷移を網羅したわけではない。

## 安全性

監査用のアカウント／人格データはPlaywrightの一時ブラウザー内にのみ作成。保存データ読み込みダイアログは確認画面を表示するところまでで、適用ボタンは実行していない。監査画像はPRの有効期限付きGitHub Actions Artifactに保存する。
