# 使い方ガイド再監査：情報量ではなく探しやすさを優先

- 監査日：2026-10-26
- 対象：アプリ内「使い方」、初心者向けMarkdown、図解、ヘルプ回帰テスト
- 対象課題：表示が縦に長い、目的を見つけにくい、見出しの折返しが不自然、説明を増やした結果UIが過密になっている
- 制約：公開アプリの実ブラウザー表示・実機タップは未検証。CIの結果はPR上で確認する。

## 第1回レビュー：以前の改善が失敗していた理由

1. **読む前にスクロールを要求していた。** 説明カード8件、常時表示の図解3つ、常時開いた人格編集説明が並び、目的にたどり着く前に大きな縦スクロールが必要だった。
2. **目立つものが多すぎた。** 大きな見出し、カードの余白、アイコン、色付き枠が反復し、どの要素が重要か分かりにくかった。
3. **検索がなかった。** 「硝子窓」「同期MAX」「サポートパッシブ」「保存」など具体的な操作名から直接探せず、利用者はカテゴリと長文を読み進める必要があった。
4. **図解を先に全部見せていた。** 複雑な操作の助けになる図も、用のない人にとっては縦長の負担になっていた。
5. **見出しに幅制限をかけていた。** 長い見出しを狭い幅で折り返すため、間延びした改行に見えた。
6. **説明と操作が同じレベルに並んでいた。** 読むだけでよい補足と、押すべきボタン・移動先が同じカード内で競合していた。

## 第2回レビュー：構造をどう変えるか

| 変更 | 目的 | 再レビューで見る点 |
|---|---|---|
| 見出しを短い「使い方」にする | 不自然な折返しの原因を取り除く | 狭幅でも見出しが無理なく収まる |
| 検索欄を最上部に置く | 機能名・目的・ボタン名で直接検索する | 検索欄が初期表示で見え、結果がすぐ絞られる |
| 分類フィルターを横一列にする | 長いメニューを縦に積まずに分類する | モバイルでは横スクロールでき、項目が潰れない |
| 大カードをコンパクトな行にする | 一度に見渡せる項目数を増やす | アイコン・余白・枠が文章より主張しない |
| 詳細を項目単位で開く | 説明を必要なときだけ読む | 最初はタイトル一覧のみ、開くと操作経路と詳細が出る |
| 図解は該当項目を開いた時だけ表示 | 複雑な操作は視覚支援しつつ、初期表示を短くする | 図のない項目まで余分な画像が出ない |
| Markdownの図を折りたたむ | 詳細マニュアルも初期の縦長化を防ぐ | 目的別一覧を先に読め、図は必要な人だけ展開する |

## 実装した変更

- アプリ内「使い方」を検索欄・分類フィルター・コンパクトな索引に再設計。
- 初期表示は「よく使う」6項目だけにし、その他は分類タブか検索で表示。
- 1行を選ぶと、詳細説明・操作経路・直接移動ボタンが開く。
- 取り込み・アカウント共有・保存の図解を、該当項目の詳細を開いた場合に限定。
- 長い案内見出し、説明カード群、常時開く人格編集カードを初期表示から削除。
- 人格手動編集・所持ビルド保存の詳細は検索可能な折りたたみ項目に移動。
- standalone Markdownの先頭に目的別索引を配置し、全体図や複雑な図は折りたたみ式に変更。
- テストを更新し、検索・分類・折りたたみ・図解の遅延表示を検査する。

## 再レビュー結果

- **情報量：初期表示を削減。** 詳細は削除せず、クリック時だけ表示する設計にした。
- **目的の発見性：改善。** 文字列検索・分類・一覧の3経路がある。
- **縦の長さ：改善見込み。** 初期画面では小さな行が並び、長文と図は閉じている。
- **改行：原因を除去。** 長い説明文を見出しにせず、短い「使い方」に置き換え、最大幅を解除した。
- **残るリスク：実ブラウザー未確認。** 実際の折返し、横スクロール、タップ領域、検索結果の高さはCIだけでは保証できない。

- 検索欄はReactイベントの`target.value`から値を取得し、入力時は全項目検索、分類ボタンから結果を絞り込む動作にした。

## 検証

- 追加テストで、検索入力、分類フィルター、折りたたみ詳細、該当項目内だけの図解表示を検査する。
- アセットの内容ハッシュとService Worker precacheを同期。
- 実ブラウザー上の表示・操作確認は別途必要。確認せずに視覚品質まで保証したとは扱わない。
