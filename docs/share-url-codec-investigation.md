## 現在の最大構成測定

| 指標 | 測定値 |

現在のdeflate-raw圧縮だけでは、長文の公式データを共有状態内に重複保存するため不十分である。

## 可逆短縮の方針

GitHub Pages上の`data/db.json`には、人格だけでなくE.G.O（`rank`+`no`）、サポート・死亡後パッシブ・強化・精神（各`name`）が含まれている。共有URLでは、DBと完全一致する公式データを短い参照へ置き換え、共有ページ側でDBから展開する。

| 共有要素 | 短縮表現 | 復元元 |
| --- | --- | --- |
| 人格基礎データ | `mode` + `no` + `name` | `normal_personas` / `tokui_personas` |
| E.G.Oスロット | ランクごとの`no` | `egos` |
| サポート・死亡後パッシブ | `name` | `support_passives` / `death_passives` |
| 強化 | `name` + 系統 | `normal_enhancements` / `special_enhancements` |
| 精神 | `name` | `spirits` |
| 公式アイテム | 既存の`itemId` | `items.json` |
| 編集済み・オリジナルデータ | 完全な差分 | URL内 |

この方式は情報を落とさない。DBと一致する状態は参照へ置換し、少しでも編集された状態は完全なオブジェクトを残す。受信側は公式DBを取得して可逆展開する。

公式データ参照を人格以外にも展開し、最大構成のE.G.O、サポート、死亡後パッシブ、強化、精神、公式複製アイテムを短い参照へ置換した。測定結果は次の通りである。

| 指標 | v64r74 | v64r75 |
| --- | ---: | ---: |
| スナップショットJSON | 14,291 bytes | 3,213 bytes |
| URL長 | 5,567文字 | **1,563文字** |
| Discord本文の実用長（1,900文字） | 超過 | **収まる** |

編集済み・オリジナルの文字列はURLに完全に残り、公式DBと一致するデータだけを参照化する。したがって、情報を削らずに通常の最大構成をDiscord等のURL扱いへ収められる。
