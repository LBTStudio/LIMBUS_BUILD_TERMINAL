# カポ最大構成 — 短縮共有IDの限界テスト

テスト日: 2026-08-18

## 構成

東部親指カポIIII（特異・同期000・同期MAX）を基準に、全317件のサポートパッシブ、全73件の通常／特殊強化、DB内35種の公式アイテム、各ランクで最長のE.G.O 5件、最長の精神「規律」、死亡後パッシブ「愛着」を含めた。

圧縮トークンは5,526文字だったが、外部保存を内部利用した最終LBT共有URLは93文字に収まった。

```text
https://lbtstudio.github.io/LIMBUS_BUILD_TERMINAL/share.html?s=t:LBT-Share-08-18-2,r:qt45ownr
```

## 検証経過

主Telegraph IDを含む共有URLでは、公開GitHub Pages上で人格・同期MAX・HP/SAN・E.G.O・全サポートパッシブまで復元できた。Rentryの単独IDでは、ブラウザの直接取得がCORSで失敗するケースを検出したため、公開互換のテキスト取得経路を予備復元へ追加してmainへ反映した。公開反映後のRentry単独復元は外部取得待機中であり、完了状態を続けて確認する。

公開ビューアの初回読み込みでは一度`Failed to fetch`となった。しかし同一ページ上で`tokenFromExternalSource`を再実行すると、Rentry ID `qt45ownr`から有効な圧縮トークンを取得できた。これは保存データの欠落ではなく、初回ネットワーク取得の一時失敗または読み込みタイミングに関係する事象として扱った。

Rentry直取得と公開互換読み取りの各通信に6秒の時間上限を付け、共有ビューア側にも800ms待機後の再試行を加えた。`?s=r:qt45ownr`だけを含む公開URLで最終的にカポ最大構成の全内容を復元でき、主Telegraph保存を含む通常の短縮URLと予備Rentry保存の双方を検証できた。
