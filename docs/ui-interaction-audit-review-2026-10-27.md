# UI操作経路のスクリーンショット監査 — 2026-10-27

## 監査方法と範囲
Playwright／Chromiumの一時ブラウザープロファイルで、デスクトップ想定 (1440×1000) とスマートフォン想定 (390×844、タッチ有効) を巡回し、計94枚を採取した。起動時のSINNER SELECT、アカウント作成・編集・共有URL取込、ビルド8タブ、ショップ分類、記録の取り込み入口、使い方検索、クイック検索、操作・保存シート、ホバー／キーボードフォーカス、保存データ読み込み確認を含む。

これはブラウザーベースの確認であり、実機iOS／Androidのキーボードやスクリーンリーダーを完全に代替するものではない。監査用の合成データを一時プロファイルに投入し、インポートは確認画面までで確定しない。

## 確認した問題と対応

### P1 — モバイルのプレビュー開閉タブが見出し／タブ列に重なる
390px幅のスクリーンショットで、縦長の「展開」タブがセクション見出しとビルドタブ列の領域に重なり、見出しの末尾が折り返されていた。
**対応:** 640px以下ではプレビュー操作を右端の縦タブから下部ナビゲーション上の横長ボタンへ移し、旧PREVIEW再開ボタンを隠して入口を一つにする。

### P1 — ビルド／記録タブ列が横方向に切れて見える
ビルド8タブと記録6タブが横スクロールになっており、後半の機能を見つけにくい。
**対応:** ビルドを4列×2段、記録を3列×2段、ショップ分類を3列×2段にし、最低44pxのタップ領域を確保する。

### P1 — セーブデータ読み込み確認が縦に長く、操作ボタンが下へ押し出される
最小のサンプルでも空のカテゴリが一列ずつ並び、適用／キャンセルがスマホ画面下部で見切れかけていた。
**対応:** データを含むカテゴリを先に表示し、空カテゴリは「データのないカテゴリも表示」に折りたたむ。項目リストだけをスクロールし、適用範囲と操作列を見える領域に固定する。初期フォーカス、Escape、Tab循環、背景クリックによるキャンセルを保持する。

### P1 — 共有URL取込フォームとオンライン保全パネル／別カードが競合する
取り込み中も下部のオンライン保全パネルと他アカウントカードが同時に見え、長いフォームに割ける高さを減らしていた。
**対応:** 取り込み中は保全パネルと編集対象以外のカードを一時的に隠し、対象カードを全幅・内部スクロールにする。終了／キャンセル後は一覧に戻す。

### P2 — アカウントカードの最終更新と「編集」が重なる
スマホ画像では「最終更新 たった今」の行がカード下部の編集ボタンに隠れていた。
**対応:** カード高を増やし、下部操作列の領域を確保する。

### P2 — 日英併記の見出しで日本語の末尾1文字が孤立する
「OWNED PERSONAS / 所持人格」で「格」だけが次行に残った。
**対応:** 英語と日本語を別々のspanに分け、日本語側の途中で改行しない。

## 誤判定防止と限界
- 取り込み画面を開いた後に撮影スクリプトが次の操作へ進めない場合、UI不具合と決めつけず、明示的な閉じる操作を使って状態をリセットする。
- ドキュメント全体の横はみ出しがなくても、内側のタブ列がスクロールして候補を隠している場合があるため、スクリーンショットを合わせてレビューする。
- 監査中の `/cdn-cgi/rum` 404はローカル静的サーバーがCDN計測URLを処理しないためのもので、アプリのJS例外とは区別する。
- 本修正のマージ判断は、修正後のデスクトップ／スマホ想定アーティファクトを再取得し、変更箇所の実画面で確認してから行う。
