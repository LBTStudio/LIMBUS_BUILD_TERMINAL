# UI操作経路監査レビュー — 2026-10-27

## 監査範囲
Playwright／Chromiumの一時ブラウザープロファイルで、デスクトップ (1440×1000) とスマートフォン想定 (390×844) の実描画を撮影。起動時のSINNER SELECT／アカウント作成、ビルド内タブ、人格リスト、各取り込み入口、ショップ分類、記録の取り込み、使い方検索、クイック検索、操作・保存シート、免責事項、アカウント編集、保存データの読み込み確認、ホバー／フォーカスを巡回した。

これはブラウザーベースの確認であり、実機のタッチ・OSソフトキーボード・全てのデータ分岐を完全に代替するものではない。撮影データは合成の監査用データのみを使用し、取り込みの確定や保存は行わない。

## 確認できた問題と対応

### P1 — 記録の取り込みパネルを開いても画面に現れない
「記録 → リザルトを記録 → 取り込む → テキスト流し込み」で状態は切り替わるが、追加パネルが画面の下方に描画され、利用者の表示位置が動かない。このためボタンを押しても反応が無いように見える。コードを読み、撮影スクリプトの失敗ではなく実際の操作導線の問題と判定した。

**対応：** テキスト、硝子窓、一括所持人格リストのパネルが開いたとき、対象パネルへスクロールし、最初の入力欄にフォーカスする。prefers-reduced-motion を尊重し、開いただけでデータを確定しない。テストでは表示位置・入力欄の可視性を検証し、解析プレビューまで撮影する。

### P1 — スマホのビルド／記録タブが横方向に隠れる
390px幅ではタブ列が横スクロールになり、後半のタブが切れて見える。スクロール可能なことが視覚的に自明ではなく、機能を見つけにくい。

**対応：** 640px以下ではビルドと記録のタブを4列の2段グリッドにし、全項目を一目で示す。高さが増える代わりに、存在する機能を隠さない設計にする。

### P2 — 日本語見出しの最後の一文字だけが次行へ落ちる
「OWNED PERSONAS / 所持人格」のような英日併記の見出しで、日本語の末尾だけが一文字残るケースを実画面で確認した。

**対応：** 見出しの英語部分と日本語部分を個別のspanに分け、日本語側を分割しない。小画面では文字サイズと行間を抑え、プレビュー操作ボタンと見出し／補助文の領域も分離する。

### P1 — 共有URL取り込みフォームと背後のアカウントカードが重なる
実画面のスマホ撮影で、アカウント編集内の長い共有URL取り込みフォームと、背後の「新しいアカウント」カードが同じ領域に現れ、見出しや説明文が重なることを確認した。フォームを閉じてから別カードを選ぶ設計でよいので、同時表示は不要。

**対応：** 共有URL取り込み中はカード群を1列にし、編集対象以外のカードを一時的に隠す。任意のクラウド保全パネルも退避し、カード群自体はスクロール可能にする。取り込み終了またはキャンセルで通常の一覧へ戻す。

### P1 — 画面上にプレビュー開閉ボタンが二重に表示される
DOMとスタイルを照合すると、LivePreviewが常設する「◀ 格納／▶ 展開」と、Appが別途描画する「PREVIEW ◈」の二つが存在していた。古い `.preview-reopen` は格納時のCSSルールの詳細度が高く、一般の `display:none` で隠れず、スマホの見出しやタブ列に重なっていた。

**対応：** 既存の `#lbt-preview-edge-toggle` を唯一の操作として残し、古い `.preview-reopen` は格納時にも表示しない。監査スクリーンショットと診断manifestで、モバイル上の重複コントロールとヘッダー領域への重なりを検出する。

## 誤判定を修正した点
- 前回のスクリーンショットで疑った「プレビュータブの重なり」は別の新しい画像では小型化済みの状態が確認されたため、現行の確定バグとは断定せず、レスポンシブ回帰を監視する対象とした。
- 保存データ読み込み画面は、データのないカテゴリが既定で折りたたまれていた。よって「全14カテゴリが常に展開され画面を圧迫する」という前回の評価は撤回する。テストは実際に存在するカテゴリと、展開操作後の挙動を区別すべきである。
- アカウント編集の詳細モーダルを撮影したあと、監査スクリプトが明示的に閉じずに続行していた。このため後続の画面がモーダルに覆われ、実際のUI問題と撮影側の状態残留が混ざっていた。詳細モーダルは撮影後に閉じ、必須の後続画面が撮れていない場合はジョブを失敗させるようにした。
- 最初の撮影ジョブは、可視性をopacityやaria-hiddenまで見ずに判定し、記録の取り込み画面を十分に検証できていなかった。監査スクリプトを改善し、取り込み後のパネルが表示域に入らなければ失敗扱いとする。

## 検証範囲・残る制約
- CIの既存テストと新しい回帰テストを実行し、デスクトップ／スマホ想定の画面を再撮影する。
- スマホの実機、実際のiOS／Androidソフトキーボード、スクリーンリーダー、マウス操作のないタッチ環境は、このCIだけでは保証しない。
- UI修正はマージ前のPRで確認し、アプリ本体の運用データを監査用途で変更しない。
