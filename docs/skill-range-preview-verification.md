# プレビュー展開時のスキル「範囲」フィールド検証記録

## 原因と修正

スキル編集の「種別・大罪・範囲・対象人数」は、常に各112px以上を必要とする3列グリッドだった。プレビューを展開すると、編集領域だけが狭くなっても画面全体のメディアクエリは変化しないため、範囲フィールドを含むメタ帯がカード外へ押し出されていた。

スキル編集カードをコンテナ基準に変更した。メタ帯は通常3列、カード幅560px未満で2列、360px未満で1列になる。各フィールドと`select`・`input`には`min-width: 0`、`max-width: 100%`、`box-sizing: border-box`を設定し、選択肢が長くてもカードの外へ広がらないようにした。

## 実画面・幅測定

プレビュー展開状態のPC実画面で、スキルカード幅は788px、通常のメタ帯は3列（各235px）で横オーバーフローなしだった。さらにプレビュー展開で狭くなる状態をスキルカード自身の幅で再現し、520pxでは2列（各245px）、340pxでは1列（各318px）となり、いずれもメタ帯の横オーバーフローがないことを確認した。

| スキルカード幅 | メタ帯 | 範囲フィールド | 横オーバーフロー |
| ---: | --- | --- | --- |
| 788px | 3列 | カード内に収まる | なし |
| 520px | 2列 | 範囲と対象人数を次行へ配置 | なし |
| 340px | 1列 | 範囲を単独行で表示 | なし |

390px相当では既存の単列編集レイアウトを維持する。プレビューの展開・格納、下側スキル一覧の選択方式には変更を加えていない。

## 自動テスト

`tests/skill-meta-preview-layout.test.mjs`を追加し、「範囲」フィールドがメタ帯に属すること、3列・2列・1列のコンテナ幅規則、フィールド自身の幅制限を回帰条件として固定した。`tests/*.test.mjs`の全回帰実行も成功している。
