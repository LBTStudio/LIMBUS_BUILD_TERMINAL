# 共有HTML レイアウト・視認性監査

- 対象日: 2026-10-22
- 対象: `js/generator.js` の `buildShareSheetHTML()` が生成するキャラクター共有HTML
- 方法: 生成テンプレート、CSS変数、見出し・折り畳み構造、出力対象、既存のモバイル監査記録をコードレビュー。主要配色のコントラスト比を sRGB 相対輝度から計算。
- 制約: 今回の接続環境では、任意の共有データ付きページを実ブラウザーで操作してスクリーンショット比較することはできていない。下記はコードと配色値に基づく監査であり、公開ページの実機視覚確認の代替ではない。

## 総評

共有HTMLは最大幅960pxの中央配置、狭幅でのステータス2列化、スキルカードの自動折り返し、ネイティブ `details/summary`、見出し階層、キーボードのフォーカス表示、動きを抑える設定を備えている。主色の本文コントラストも十分高い。

一方、本文そのものの字は小さめで、色タグの一部は白字とのコントラストが不足している。折り畳まれた情報の量が分からず、印刷用CSSは本文色と折り畳み状態を十分に扱っていなかった。このため、内容の欠落というより「読みやすい密度に整える」「隠れた内容の存在を伝える」「印刷時に情報を失わない」改善を優先する。

## 指摘と対応

| 優先度 | 観点 | 点検結果 | 対応 |
|---|---|---|---|
| 高 | 色タグのコントラスト | `#c96424` の白字は3.94:1、`#e29a20` は2.37:1、`#7a9b40` は3.19:1、`#9a989b` は2.86:1。いずれも通常サイズの本文相当テキストで4.5:1を下回る。タグ文字は11pxで、影だけに頼るのは不安定。 | 色欲・怠惰・暴食・特殊のタグを暗色文字 `#17120d`、テキスト影なしに変更。各背景に対して4.72:1以上。 |
| 中 | 効果本文・ダイス説明 | 一般効果本文とサポートパッシブ本文が12.5px、行間1.7。ダイス本文も12.5pxで、情報量の多い共有シートを長く読むと負担になりやすい。 | 本文とダイス説明を13.5pxへ、行間を1.8（ダイス1.7）へ拡大。タイミング見出しと効果ラベルも僅かに拡大し、見出しの装飾的な字間を縮小。 |
| 中 | 折り畳みの発見性 | E.G.O・サポートパッシブは初期状態で閉じている。展開案内は9pxで、折り畳み内に何件あるか分からない。内容があることや量が見えにくい。 | 案内を10.5pxへ拡大し、E.G.O・サポートパッシブの見出しに件数を追加。展開操作自体は既存のネイティブ `details/summary` を維持。 |
| 中 | 印刷・PDF保存 | 印刷CSSはbodyの背景色と文字色だけを変更していた。本文・注釈はCSS変数で明るい文字色を持ち続けるうえ、閉じた `details` の内容は印刷で欠落する可能性がある。 | 印刷時のCSS変数を白地・濃色文字へ切替え、折り畳みの本文を表示、カード内の改ページを抑制、装飾影を除去。 |
| 低 | 狭幅・長い名前 | CJKは自然に折り返せるが、連続した英数字などを含むPC名・人格名に折返し指定がなく、狭幅で横にはみ出す可能性がある。 | ヘッダー名へ `overflow-wrap:anywhere` と `min-width:0` を追加。 |

## 維持する点

- ダーク基調と金色の見出し、罪属性・E.G.Oランクの識別は維持。
- 本文の色変数 `--tx2: #d9d0c0` は暗いパネル背景に対して約11.7:1であり、本文色そのものを変える必要はない。
- スマートフォンでのステータス2列、スキルカードの自動折り返し、意味のある見出し階層、折り畳みのフォーカスリング、`prefers-reduced-motion` 対応は維持。
- 共有HTMLはアプリ本体と独立した1枚のHTMLなので、印刷・タイポグラフィの指定は生成HTML内に保持する。

## 回帰確認

`tests/shared-html-layout.test.mjs` を追加し、生成HTMLを対象に本文・ダイス文字サイズ、色タグのコントラスト、折り畳み件数、印刷時の本文表示、長い名前の折り返しを固定する。 `index.html` と `share.html` の `generator.js?v=` は生成ファイルの内容ハッシュに同期する。

## 残る確認

本PRではブラウザー実表示のスクリーンショット回帰は未実施。マージ前に少なくとも320px・390px・640px・1440px相当で、長い人格名・最大数のスキル／E.G.O・展開状態・印刷プレビューを確認することを推奨する。折り畳みを開いた状態で本文が横にはみ出さないか、印刷で閉じたセクションが全件表示されるかは特に確認対象。


## 2026-10-23: 検索による折り畳みの自動展開

ブラウザー標準のページ内検索（Ctrl+F）は、閉じた `details` 内の一致箇所を表示するため、検索ヒットの祖先を自動展開することがある。これはChromium系ブラウザーの標準挙動であり、標準検索自体を抑止すると、閉じた項目内のヒット位置へ移動して内容を見せることもできなくなる。

共有HTMLには専用の「このシート内を検索」を追加した。この検索は `textContent` から折り畳み内を含むテキストを検索し、ヒット件数・分類・項目名・抜粋を表示する。検索入力だけでは `details.open` を変更しない。結果の「この項目を開く」を利用者が押した場合に限り、該当項目の祖先の折り畳みを開き、該当カードへスクロールする。検索結果の文字列は `textContent` で追加し、ユーザー入力をHTMLとして解釈させない。

専用検索欄の案内を追加し、Ctrl+F / Cmd+F は `window` のキャプチャ段階で先に捕捉して既定アクションを止め、専用検索欄へ誘導する。ページへキーイベントが届く環境では、後続のページ内ハンドラーが同じキーを処理して標準検索が起動する競合も避ける。ブラウザーのメニューなど、ページ側でショートカットを捕捉できない方法で標準検索を起動した場合は、ブラウザー側の自動展開が引き続き起こる場合がある。この挙動と専用検索の回帰テストを追加した。実ブラウザーでの操作確認は別途必要。

## レビュー指摘への対応（2026-10-23）

外部監査（Chromium による実ブラウザー実測を含む）で3点の指摘を受け、次のとおり修正した。実測の詳細は指摘元の監査記録に譲る。

| 指摘 | 実測結果 | 対応 |
|---|---|---|
| Ctrl+F／Cmd+F を無効化していた | キャプチャ段階の `preventDefault` + `stopImmediatePropagation` で標準検索が起動しない | **標準検索を無効化しない。** 専用検索は並存する追加の手段とし、ショートカットの捕捉は撤回した |
| 専用検索の対象が限定されていた | ヘッダー（PC名・人格名）とフッタが検索結果に出ない（人格名で0件） | 検索対象に `.hd`（ヘッダー）と `.foot`（フッタ）を追加した |
| 印刷時に閉じた折り畳み本文が出ていなかった | 全展開時との本文高さ差 727px。閉じた `details` の子要素は高さ0で、`display:block!important` では内容抑制を上書けない | CSS による強制表示を撤廃し、`beforeprint` で全 `details` を展開 → `afterprint` で元の開閉状態へ復元する方式へ変更した |

回帰テストも更新した：標準検索を無効化しないこと（ハンドラ不在）、検索対象にヘッダーを含むこと、印刷ハンドラの存在、そして CSS 強制表示の不在を固定する。
