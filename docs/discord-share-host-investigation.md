# Discord共有URLホスト調査

調査日: 2026-08-17

## 判明した点

| 既存共有先 | 検証結果 | Discordカード用の採用可否 |
|---|---|---|
| 0x0.st | 2026-08-17時点でアップロード停止の応答を返した。 | 不可 |
| Uguu | HTMLをファイル形式として受け付けず、415を返した。 | 不可 |
| Filebin | HTMLを`attachment`としてS3署名URLへ302する。DiscordクローラーがページのOGPを読めない。 | 不可 |
| temp.sh | 公開URLがアップロードHTMLではなく、独自のダウンロード案内HTMLを返した。 | 不可 |
| Catbox / Litterbox | この調査環境ではアップロード応答がタイムアウトした。実際の発行URLを取得して別途検証する必要がある。 | 未確定 |

Filebinの公開URLは`response-content-disposition=attachment`を付けたS3署名URLへ302し、temp.shはアップロード済みHTMLではなくダウンロード案内用の独自HTMLを返すことを、非個人情報のOGPテストHTMLで確認した。

また、0x0.stのアップロード停止、UguuのHTML形式拒否により、現行の7ホスト並列レースは実質的に失敗・遅延する送信を多数含んでいる。各送信は最大25秒待機するため、成功先が早く返らないケースでは発行画面が長時間待機状態になり得る。

既存実装は複数ホストへの並列アップロードで最初に生存したURLを採用していた。この方式では、リンクを開けるだけのダウンロードホストが選ばれ、Discordがページ内のOGPを取得できないことがある。

## 次に必要な情報

実際にDiscordでカードが表示されなかった発行URLを1件取得し、HTTPレスポンス、最終リダイレクト先、`Content-Type`、`head`内のOGPを直接確認する。

## 承認済みのHTMLSaveテスト

利用者の確認を得たうえで、キャラクター情報を含まないOGPテストHTMLをHTMLSaveの公開フォームへ入力した。内容はタイトル、説明、種別、LBTの静的共有画像だけであり、実データ・保存データ・個人情報は送信しない。

公開送信時、HTMLSaveは「Sign In First」と応答した。ログインなしでは公開できないため、LBTのアカウント不要な自動共有先としては採用できない。

## Netlify Drop候補

Netlifyは匿名のドラッグ＆ドロップ公開を提供しており、単一の`index.html`またはZIPを投入すると公開URLが作られると案内している。公開リンクはデフォルトで第三者が閲覧可能である。[Netlify Drop](https://app.netlify.com/drop) はブラウザのファイル入力を提供する一方、現時点ではLBTから認証なしで使える安定したHTTPアップロードAPIを確認できていない。したがって、実装候補として調査を続けるが、確認前に自動共有先として採用しない。

この検証ブラウザでは`app.netlify.com/drop`のアプリ領域が空白となり、ファイル入力を利用できなかった。画面上での匿名デプロイ成功まで確認できていないため、この時点では発行先に追加しない。

## 静的ビューア用データホストの追加検証

GitHub Pages上の静的な共有ビューアで、外部に保存した状態JSONを復元する案も検討した。

| 候補 | 保存 | 読出し応答 | 結論 |
| --- | --- | --- | --- |
| paste.rs | 匿名POSTで成功 | `text/plain`、`Access-Control-Allow-Origin`なし | GitHub Pagesのブラウザから`fetch`できないため不採用 |
| Catbox | 匿名POSTで成功 | `text/plain`、`Access-Control-Allow-Origin`なし | 静的ビューアの状態取得に使えない。HTMLを直接開いてもOGPカードを保証できないため不採用継続 |
| hastebin.com | 匿名POST | HTTP 401 | 匿名保存が使えないため不採用 |
| Uguu | JSONファイルとして送信してもHTTP 415 | 保存不可 | 不採用 |

このため、外部ストレージに依存しない共有URLのみでは、URL長の上限を超える完全なビルドデータを安定して渡せない。Discordが取得するOGPを動的に人格名へ差し替えるには、静的GitHub Pagesではなく、リクエストごとにHTMLを返せるサーバー側の共有ストアが必要である。
