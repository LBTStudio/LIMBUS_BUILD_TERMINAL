# 最大構成・自己完結共有URLの実測

検証日: 2026-08-17  
対象バージョン: LBT v64r75

## 構成

DB内のJSON表現が最長だった特異人格 **東部親指カポIIII**（No. 14、8スキル、3,262文字）を選んだ。その上で、全ランクE.G.Oを1件ずつ、全317件のサポートパッシブ、最長の死亡後支援、全68件の強化、最長の精神、全35種類の公式アイテムを積載し、同期IV・同期MAXを設定した。

| 要素 | 件数 | 検証での扱い |
| --- | ---: | --- |
| 人格 | 1 | DB内で最長の東部親指カポIIII |
| E.G.O | 5 | ZAYIN / TETH / HE / WAW / ALEPH 各1件 |
| サポートパッシブ | 317 | DBの全件 |
| 死亡後支援 | 1 | JSON表現が最長の1件 |
| 強化 | 68 | DBの全件 |
| 精神 | 1 | JSON表現が最長の1件 |
| 公式アイテム | 35 | DBの全件 |

## 実測結果

| 指標 | 実測値 |
| --- | ---: |
| 元の共有状態JSON | 57,972文字 |
| 圧縮トークン | 5,570文字 |
| GitHub Pages自己完結URL | 5,635文字 |
| Discord本文2,000文字以内 | いいえ |
| 可逆復元したE.G.O | 5件 |
| 可逆復元した支援 | 317件 |
| 可逆復元した強化 | 68件 |
| 可逆復元したアイテム | 35件 |

自己完結URLはGitHub Pagesで実際に開き、人格名・同期MAX・全ランクE.G.O・サポートパッシブの展開領域を含めて表示されることを確認した。

> この実測は、現在のURL内共有が中程度の共有には有効である一方、最大構成の長文共有ではDiscord本文上限を超えることを再現する。そのため、短い外部公開URLへ可逆データを保存する分散長文共有方式が必要になる。
