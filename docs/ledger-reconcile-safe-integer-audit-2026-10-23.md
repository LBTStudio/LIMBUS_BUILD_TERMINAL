# 通帳収支の安全整数検証監査（2026-10-23）

## 発見：有限だが安全整数でない額を有効な収入／残高として受理する

`js/ledger-import-reconcile.js` の数値パーサーは、整数フォーマットの検証後に `Number.isFinite` だけを確認していた。JavaScriptでは `9,007,199,254,740,993` のような値が有限な `number` に変換されても、安全整数の範囲外で正確に表せない。これを通帳の収入や現在残高として採用すると、帳尻合わせの差額が丸められ、誤った支出額を提案する可能性がある。

## 修正

- パース結果を `Number.isSafeInteger` で検証する。
- 上限 `Number.MAX_SAFE_INTEGER` は引き続き許可し、それを超える収入は `invalid-income`、残高は `no-current` として指摘する。
- 回帰テストで上限値と上限超過のカンマ区切り入力を検証する。
- `index.html` のJS版ハッシュおよび `sw.js` のプリキャッシュ／キャッシュIDを更新する。


同じ入力経路では負の収入・負の残高も有効として受理しない。収支入力UIは収入と残高を表すため、負数を補正値として黙って扱わず、収入は invalid-income、残高は no-current の警告に回す。


また、入力ごとに安全整数範囲内でも、前回残高＋収入−現在残高の算術結果が安全整数範囲を越え得る。導出した支出額も Number.isSafeInteger で検証し、超過した場合は null と明示的なエラーを返して誤った金額を確定しない。
