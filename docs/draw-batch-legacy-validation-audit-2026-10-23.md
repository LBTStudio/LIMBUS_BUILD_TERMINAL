# 抽選バッチの旧形式互換・ペイロード監査（2026-10-23）

## 発見

`validateDrawRecordShapes` は旧バッチ互換のため `item.kind` 欠落を許容している一方、`rosterAddsFromDrawBatch` は `item.kind` だけで通常人格・E.G.Oの変換先を判定していた。このため、旧形式の `record.kind` を持つ記録が検証・支払いを通過しても所持へ追加されず、通帳／証明と所持の差が生じる可能性があった。

さらに、人格/E.G.Oの `no` は非null確認しかなく、`0`、負数、小数、文字列等が検証を通る余地があった。人格の `mode` とレコード種別、E.G.Oのランクも十分に照合していなかった。

## 修正

- 所持への変換では `record.kind` を正本にし、旧形式の `item.kind` 欠落を許容しつつ通常人格／特異人格／E.G.Oへ変換する。
- 人格・E.G.O番号は正の安全整数（整数数字の文字列も互換として許容）に限定。
- 人格モードは record.kind と矛盾する値を拒否。
- E.G.OランクはZAYIN/TETH/HE/WAW/ALEPHに限定。
- 回帰テストで、旧形式のitem.kind欠落でも所持と通帳支出が反映されること、不正形状が確定前に拒否されることを確認する。

## 保証範囲

この修正は、UIやインポートから流入する不整合データを取引確定前に止めるもの。抽選証明のseed/rollsと当時の候補プールから結果が完全に導出されることの数学的な検証は別課題。
