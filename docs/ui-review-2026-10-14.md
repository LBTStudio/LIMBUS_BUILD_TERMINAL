## 実バグ（修正済み・ブラウザ実測で確認）

### 1. 「駒整形」だけ画面タイトルが存在しなかった（重要）
`App.js` の `renderSection` が `baseinfo` ケースで `SectionTitle` を描画していなかった。他 3 画面
（roster / help / settings）は描画しているのに 1 画面だけ欠けていたため、本文が
`CHARACTER NAME` の入力欄から始まっていた。`SECTIONS` には `title: "BASE INFO"` /
`subtitle` が定義済みにもかかわらず未使用だった。

修正: `baseinfo` にも `SectionTitle` を渡す。実測で `01 / BASE INFO / 装備人格の同期・固有バフ・戦闘設定` が出ることを確認。

### 2. 「アカウントを切替・管理」ボタンが重複していた（中）
`accounts-ui.js` の `AccountSummary` 内と `OtherSections.js` の `SettingsSection` 内が、どちらも
`ACCOUNTS_OPEN_EVENT` を発火する同一ラベルのボタンを描画していた。設定画面で縦に 2 個並ぶ。

修正: `AccountSummary` 側を削除し、導線を 1 つに。実測でボタン数 = 1 を確認。

### 3. `?v=` が古く 2 テストが落ちていた（中・運用）
上記 2 修正を HEAD に取り込んだ際 `tools/sync-asset-versions.mjs` が走っておらず、
`index.html` の `?v=` が実ハッシュと不一致。`sync-asset-versions` 実行で解消。

## 撤回した誤検出（記録に残す）

1. **「クイック検索が ESC で閉じない」→ 誤り。** 検出器の `offsetParent !== null` が
   `opacity: 0` の要素にも true を返すため、閉じているのに開いていると判定していた。
   正しい可視判定（`opacity`/`pointer-events` 込み）に直して再測し、ESC で閉じることを確認。
2. **「ショップのカードが全部赤」→ 誤り。** 赤は罪（`--sin-*`）のカテゴリ色で、
   「購入不可」ではない。`data-blocked` は別に付与されている。
3. **「ガチャ説明文の日本語が壊れている」→ 誤り。** 低解像度スクリーンショットの読み取りミス。
   DOM から文字起こしすると `抽出全般。ルートごとに通貨で払うか抽出チケットを使うかを選べます。所得は直近のリザルトに帰属します。` で正しい。

## 未解決の指摘（要判断・コード未変更）

### A. 購入可否の分布がタブ間で极端に偏る（中）
新規アカウント（LP 0 / 欠片 0）で実測:

| タブ | カード数 | blocked | 割合 |
|---|---|---|---|
| サポート | 366 | 267 | 73% |
| E.G.O | 115 | **0** | 0% |
| 精神 | 45 | 45 | 100% |
| アイテム | 35 | 10 | 29% |

E.G.O 115 枚すべてが `無料` 表示かつ `data-blocked` 無し。ルール上 E.G.O 購入は欠片のはずだが、
新規アカウントで 0 枚しか blocked にならない。**価格解決かデータ側の欠落が疑われる。**
UI 監査の範疇を超えるためデータ側要確認として記録。データ未検証のため断定しない。

### B. blocked を「警告色」で塗ると情報量が落ちる（要設計判断）
`data-blocked` のカードが 267/366 ように大半になると、赤という「例外の色」が常態化し、
本来強調したい Programme（essential/expensive）の差が読めなくなる。代替案:
- blocked は枠線だけ中立色に落とし、価格バッジとツールチップで理由を語る
- 残り_axis で购买了更要なものを先頭に（`showAffordableOnly` 相当のトグル）
現状は「押すと toast で理由を出す」設計なので、 정보를捨てておらず実害は限定的。

### C. アカウント作成フォームのレイアウト均衡（軽微）
ゲートパネル（約 720px）の中で作成フォームは約 220px 幅で左寄せ。縦も上半分しか使わず、
下部空闲が大きい。中央寄せ + 最大幅の明示で解消できる。

### D. 「使い方」が薄い（軽微）
`操作ガイド` はテキスト 804 文字、折りたたみ 0 個。他画面は `details` で情報量qph を隠すのに、
使い方だけ一続き。 Cepain 導線の説明が無く、`details` 化するか策を足すと他画面と速度が合う。

## 総評

情報設計は高い。罪の色分け、E.G.O の 5 スロット（ZAYIN〜ALEPH）、所持のみ/全件のトグル、
`條件` / `効果` の 2 行構造をビルドとショップで共有しているのは一貫性があり、追跡速度を
znacząca 上げている。脆さは「例外色の滥用」と「1 画面の取りこぼし」に集約され、根本の
情報設計ではなく実装漏れに近い。
