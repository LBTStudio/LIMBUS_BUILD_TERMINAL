# 任意のオンライン保全・復旧

## この機能の前提

オンライン連携は任意です。未連携の利用者は、今まで通り `localStorage` を使ってこのブラウザー内だけで作業できます。初回表示時にデータを自動アップロードせず、アカウントの連携・復旧キーの発行・初回保存は利用者の操作を必要とします。

保全対象は、LBTがアカウントと旧保存データに使う `lbt_*` のうち、アカウント索引・各アカウントの作業状態・アイコン・旧保存の退避キーに限定しています。クラウド認証セッションや復旧キー自体は、バックアップペイロードへ含めません。

### 費用を抑えて運用する

この機能は既存のSupabaseプロジェクトを使い、Google OAuthやX Developer Platformなどの外部ログイン連携は使いません。ユーザーが発行・保管する復旧キーで保管庫を識別するため、Google側へプロフィールやメールアドレスを要求する必要がなく、Xの従量課金も発生しません。

Supabase Freeの枠内で運用する想定ですが、無料枠には容量・利用上限・稼働条件があり、無料プロジェクトは長期間使われないと一時停止されることがあります。サービスの将来の提供条件や停止リスクまで含めて永久無料を保証するものではありません。オンライン保全だけに依存せず、JSONバックアップも別の場所へ保管してください。

## 利用者向けの使い方

### ローカルだけで使う

オンライン保全パネルを無視して、そのままSINNER SELECTでアカウントを選べます。ログインや復旧キーは不要です。

### 別端末からクラウドデータを復元する

GoogleアカウントやXアカウントとの連携は実装しません。オンライン保全は復旧キーだけで利用します。別端末では、保管しておいた復旧キーを入力して「復元」を選びます。復元前にその端末にもデータがある場合は、上書き前に現在のデータをJSONファイルとしてダウンロードし、確認を取ってから置き換えます。

### 復旧キーを使う

「復旧キーを発行して保全」は、暗号学的乱数で生成したキーを発行し、全アカウントデータをオンラインへ保存します。キーはファイルとしてダウンロードされ、ブラウザーにも自動同期用として保存されます。ファイルを別の安全な場所へ保管してください。

復旧キーは単なる合言葉ではなく、保全データへアクセスできる秘密情報です。Discordや公開チャンネルに貼らないでください。キーを紛失し、JSONバックアップも無い場合はクラウドデータを復元できません。キーは初回発行時にファイルとしてダウンロードされるため、端末とは別の安全な場所にも保管してください。


### 復旧キーの有効期間とデータ更新

復旧キーは保管庫の識別子です。キーそのものはサーバーへ平文保存せず、SHA-256ハッシュだけを保存します。通常のバックアップ更新、revisionの増加、過去世代の復元、端末の追加ではキーを作り直しません。**同じ復旧キーで、更新後の最新データを引き続き取得できます。** 自動失効期限や更新回数による失効はありません。

キーが変わるのは、利用者が「復旧キーを再発行」を明示的に選んで確認したときだけです。その場合は新しいキーをファイルへ保存し、古いキーは無効になります。再発行時にもバックアップ本体と履歴は変更しません。復旧キーの紛失や漏えいに備えるため、JSONバックアップも別途保管してください。

### JSONファイルで保全・復元する

「全アカウントをJSON保存」はオンライン認証の有無にかかわらず利用でき、アカウント一覧・各アカウントの状態・アイコンなどをまとめて保存します。「JSONファイルから復元」は保存したファイルを端末に戻します。これはオンラインサービスと独立した退避方法なので、定期的に別の場所へ保存することを推奨します。

## 保存先・暗号化範囲と容量

クラウドへ保存されるJSON本体は、アプリ独自のエンドツーエンド暗号化を行いません。適切なサーバー権限を持つ管理者から内容を秘匿する設計ではありません。オンライン保全にはアカウント名、作業状態、所持データ、アイコン等が含まれるため、パスワードや秘密情報を記録しないでください。

復旧キーそのものはサーバーに保存せず、SHA-256ハッシュを検索用に保存します。ただし復旧キーは保全データへアクセスできる秘密情報です。キーのファイルは、クラウド保全データとは別の安全な場所へ保管してください。

クラウドへの1回の保存は12MBまでです。端末内JSONの保存・読込はオンライン容量と分離し、コンパクト形式で100MBまで扱えます。ただし、実際にブラウザー内へ復元できる容量はブラウザー自身の保存上限にも左右されます。復元に失敗した場合も、保存したJSONファイルは削除せず、別の端末や保存領域を使ってください。

## 実装・Supabase設定

このリポジトリのオンライン保全は、既存のSupabaseプロジェクトを利用します。Google OAuthやX OAuthは設定せず、復旧キーだけで保管庫へアクセスします。

1. `supabase/migrations/20261025211015_lbt_account_vaults.sql` を既存プロジェクトに適用します。
2. `supabase/migrations/20261025212903_lbt_account_vault_access_hardening.sql` を適用します。保管庫テーブルの直接アクセスはEdge Function経由に限定し、ブラウザーからの直接アクセスを許可しません。
3. `supabase/functions/lbt-account-recovery/index.ts` を `lbt-account-recovery` としてデプロイし、`verify_jwt=false` を指定します。関数は復旧キーの形式を検証してSHA-256ハッシュで保管庫を検索します。サービスキーはEdge Functionのサーバー環境にのみ置き、ブラウザーへ出しません。
4. Supabaseの無料枠、利用状況、プロジェクトの稼働状態を管理画面で確認します。Google Auth PlatformやX Developer ConsoleでのOAuthアプリ登録・Client ID / Secret設定は不要です。

復旧キーの初回発行時だけ、新しい保管庫を作成してその端末のデータを保存します。キー発行後のデータ更新は `backup` 操作で行い、キーのハッシュを変更しません。明示的な「復旧キーを再発行」だけがキーを差し替えます。再発行時は旧キーのハッシュと新キーのハッシュを使って競合を防ぎ、クラウドデータ本体・revision・保存履歴はそのままにします。

## 同期と衝突の扱い

- ローカル保存が常に先に行われます。オンライン同期の失敗・オフライン・サービス停止はローカル保存を無効化しません。
- オンライン保全を有効にした後だけ、アカウント保存イベントを受けて遅延同期します。再接続時にも再試行します。
- 別端末からクラウドデータが更新されている場合、古いローカル状態で自動上書きせず同期競合として止めます。
- 更新前のクラウド状態を世代履歴に保存し、直近10世代を復元できます。
- クラウドへ送る1スナップショットは12MBまで、端末内JSONの書き出し・読込は100MBまでです。ブラウザー自身の保存容量が小さい場合、100MBのJSONでも復元できないことがあります。
- オンライン保全は復旧キー方式だけを提供します。Google/XログインボタンやOAuth認証コードはありません。ローカル保存だけで使い続けることもできます。
- 新しいオンライン保管庫の作成には、接続元ごとに1時間あたり10回の制限を設けています。既存の保管庫への正しい復旧キーによるアクセスや、保存データの更新はこの新規作成制限とは別扱いです。

- 無料サービスは停止・一時停止・仕様変更・障害の可能性があります。オンライン保全だけを唯一の退避先にせず、JSONを別の保管場所にも保存してください。
