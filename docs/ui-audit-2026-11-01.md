# LIMBUS BUILD TERMINAL 全UI・操作性監査（2026-11-01）

## 監査範囲と方法

現行 main を対象に、Playwright の操作監査を再実施。PC 1440x1000、タブレット 1024x768、スマートフォン 390x844 の3幅で、SINNER SELECT、全ビルドタブ、ショップ6分類、所持ライブラリ6分類、リザルト、設定の全開閉項目、取り込み、共有、検索、保存、確認ダイアログ、ホバー、キーボードフォーカスまで踏破した。検証用のアカウント／取得履歴／報酬は使い捨てQAデータであり、利用者の実データは変更していない。

基準となった直近のUI操作監査は405スクリーンショット・102操作。コンソールエラー、HTTPエラー、ページ例外、水平はみ出し、必須キャプチャ欠落、重大レイアウト警告はすべて0件だった。ただし、従来のタップ領域チェッカーは特定の操作部品だけを選択しており、アカウントカードの編集・削除と人格のお気に入りを検査対象に含めていなかった。

## 修正した問題

### P2 — 画面切替後に前画面のスクロール位置が残る

中央の `.focus` は画面切替後も同じDOM要素を使い続ける。従来の `SET_UI currentSection` は `scrollTop` を初期化しないため、長い画面の下部から別画面へ移動すると、次画面の先頭・見出しが隠れた位置で表示され得た。

**修正:** 画面と主要サブ画面（所持タブ、ショップ分類、設定詳細、基本情報内タブ）のルートキーを追跡し、キーが変わったときだけ中央スクロールを0へ戻す。検索文字、入力、フィルターなど同じ画面内の編集ではスクロール位置を保持する。監査ハーネスに「長い人格画面の末尾からショップへ移動し、先頭へ戻る」操作回帰を追加。

### P2 — スマートフォンのアカウント編集・削除ボタンが小さい

カード内の `.acct-icon-btn` は28x28 CSS px。スマートフォンでの編集／削除操作は誤タップしやすく、既存の40px操作領域チェッカーにも含まれていなかった。

**修正:** 640px以下では編集・削除の操作領域を40x40 CSS px以上に拡大。カードの情報構造・デスクトップ寸法は変えない。

### P2 — スマートフォンの人格お気に入りが小さい

人格カードの `.p-fav` は24x24 CSS pxで、40pxタップ領域監査の対象外だった。

**修正:** 640px以下でお気に入り操作の領域を40x40 CSS px以上に拡大。視覚上の星アイコン自体のサイズと通常幅のレイアウトは維持する。

## 回帰防止

- Playwright監査に画面切替後のスクロール位置検査を追加。
- 40pxタップ領域検査にアカウントカード操作と人格お気に入りを追加。
- 利用者向けアクセスカウンター撤去後も残っていた、監査ハーネス内の旧カウンターAPIモックを削除。

## 良好だった点・維持事項

- 主要3幅でドキュメント全体の水平はみ出しなし。
- SINNER SELECTのアカウント一覧・編集カードはスクロール領域が確保され、ボタンの重なりなし。
- ショップは分類ハブから各カテゴリへ移動でき、戻る導線を保持。
- 設定は18個の開閉状態を撮影済み。
- 取り込み・共有・保存の確認画面は実操作で開閉し、適用／破壊的操作は使い捨てQA以外では実行していない。

## 監査上の制約・残課題

今回の自動ブラウザ監査は Chromium の3 viewport 幅が中心。320pxの極狭幅、実機Safari／Firefox、ブラウザズーム200%・400%、実タッチ端末の操作感は別途確認が必要。スクリーンショット／操作ハーネスは axe の全モーダル状態走査を含まないため、今回の「レイアウト警告0」をWCAG適合の保証として扱わない。外部Webフォントが利用できない環境でのフォールバック字形・折返しも別のネットワーク条件で検査する余地がある。
