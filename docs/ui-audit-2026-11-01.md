# LIMBUS BUILD TERMINAL 全UI・操作性監査（2026-11-01）

## 結論

主要な操作経路はPC・タブレット・スマートフォンのChromium実ブラウザで踏破し、画面崩れや操作性に関わる問題をPR #493で修正した。追加axe診断で見つかったスキル空状態のキーボード操作不可と複数の色コントラスト不足も、同PRで修正・回帰防止する。初回の主な問題は4系統（画面遷移時のスクロール残留、スマートフォンのアカウント操作、人格お気に入り、残高ナビゲーションのタップ領域）。追加診断ではCCFOLIAプレビュータブ、リザルト並び順、抽出パック選択、フォームボタン等の小さな操作面も検出し、40pxを確保する対象を分類して追加修正した。

自動監査はChromiumでPC 1440px、タブレット1024px、スマートフォン390px・320pxの4 viewportを通し、画面撮影時に可視となったダイアログ／シート状態は4 viewportでaxe診断する。これとは別に、全26ビュー（ホーム1、ビルド9、ショップ7、記録7、設定1、使い方1）を1440x900でaxe診断し、critical／serious違反が1件でもあればCIを失敗させる。ダイアログ／シートの診断集計と全画面診断集計はmanifest上で別フィールドに保存し、母数を混同しない。実機Safari／Firefox、200%／400%ブラウザ拡大、実スクリーンリーダーでの確認は未完了であり、WCAG適合や全ブラウザでの完全性を保証するものではない。

## 監査範囲と方法

PlaywrightでPC 1440x1000、タブレット1024x768、スマートフォン390x844・320x640を検査。スマートフォンは `hasTouch: true` にし、操作ヘルパーは `locator.tap()` を使ってタッチ経路を通す（通常クリックで代用しない）。SINNER SELECT、全ビルドタブ、基本情報・ST・ラベル・CCFOLIAプレビュー、ショップ6分類、所持ライブラリ6分類、リザルト、設定の開閉項目、取り込み、共有、検索、保存・復元、確認ダイアログ、ホバー、キーボードフォーカスを巡回した。

QAアカウント・取得履歴・報酬は使い捨てデータで検証し、利用者の実データは変更していない。SINNER SELECTの再選択はカードの実タップだけで通し、アプリ内部イベントで直接画面遷移させるフォールバックは置かない。新規作成も画面フォームの送信結果だけで判定し、作成APIを直接呼ぶ救済処理は置かない。インポート／共有の確認状態は撮影したが、適用・外部公開などの破壊的操作は行っていない。

最新の回帰監査は529スクリーンショット・4 viewport。必須キャプチャ漏れ、操作失敗、コンソールエラー、HTTPエラー、ページ例外、水平はみ出し、重大レイアウト警告はいずれも0件。画面の存在確認だけに偏らないよう、スクリーンショットとDOMの実測値を併用した。全画面axeは26/26ビュー、画面撮影時のダイアログ／シートaxeは125状態で実行し、結果は別々に集計する。

## 検出した問題と修正

### P2 — 画面切替後に前画面のスクロール位置が残る

中央の `.focus` は画面切替後も同じDOM要素を使い続ける。従来の `SET_UI currentSection` は `scrollTop` を初期化しないため、長い画面の下部から別画面へ移動すると、次画面の先頭・見出しが隠れた位置で表示され得た。

**修正:** 画面と主要サブ画面（所持タブ、ショップ分類、設定詳細、基本情報内タブ）のルートキーを追跡し、キーが変わったときだけ中央スクロールを0へ戻す。検索文字、入力、フィルターなど同一画面内の更新では位置を保持する。監査ハーネスに「ホームの末尾からショップへ移動し、先頭に戻る」回帰検査を追加。

### P2 — スマートフォンのアカウント編集・削除ボタンが小さい

アカウントカード内の `.acct-icon-btn` は28x28 CSS px。編集／削除を誤タップしやすく、旧チェッカーの検査対象にも含まれていなかった。

**修正:** 640px以下で編集・削除の操作領域を40x40 CSS px以上に拡大。カードの情報構造とデスクトップ寸法は維持。

### P2 — スマートフォンの人格お気に入りが小さい

人格カードの `.p-fav` は24x24 CSS pxで、旧タップ領域監査の対象外だった。

**修正:** 640px以下でお気に入り操作の領域を40x40 CSS px以上に拡大。星アイコン自体の見た目と通常幅のレイアウトは維持。

### P2 — CCFOLIAプレビュー切替タブと記録フォームの操作面が小さい

追加した全操作要素のDOM診断で、プレビュー切替タブが29px、リザルト並び順が38px、抽出パック選択欄が32pxとなる状態を検出した。小さい選択欄やタブはモバイルで押し損ないやすく、既存の検査セレクターにも漏れがあった。

**修正:** プレビュー3タブ、記録の並び順・抽出パック選択、ボタン／送信ボタン、モバイルフォーム入力欄を40px以上に統一。既存コンポーネントCSSの後から高さ指定が上書きされることが分かったため、全リンクCSSより後に最終モバイル補正を置き、実際の描画寸法を再検査する構成に改めた。

### P2 — スマートフォン上部の残高ナビゲーションが小さい

監査スクリーンショットのDOM寸法から、残高表示ボタンは390px幅で132x25 CSS pxと確認した。単なる数値表示ではなく、押すと記録・収支画面へ移動するボタンであり、他の主要タップ操作と比べて高さが不足していた。また旧チェッカーの明示対象から漏れていた。

**修正:** 640px以下で `.topbar-balance` の最小高さを40pxに設定し、タップ領域監査の対象へ追加。

### P2 — 320px幅で人格取得照合の開閉見出しが小さい

「PERSONA AUDIT／人格取得の照合」の開閉見出しは320px幅で高さ約34.8 CSS pxだった。全操作要素の補助計測には出ていたが、既知操作対象のセレクター一覧にsummaryが含まれず、40pxタップ領域のゲートを通過してしまっていた。

**修正:** 640px以下で当該summaryの最小高さを40pxへ拡大し、`.ledger-persona-audit-disclosure > summary` を実測タップ領域のゲートへ追加。診断ログと合否判定の対象を一致させる。

### P2 — ブラウザ起動時の404を特定できない

axe用の初期ブラウザ起動時にリソース404が1件検出されたものの、従来ハーネスはconsole文字列しか保存せずURLが失われていた。入口ページにファビコン指定もなく、ブラウザ既定のファビコン要求とアプリ資産の404を区別できなかった。

**修正:** メイン・共有・モバイルプレビューの各入口へ軽量なインラインSVGファビコンを指定。Playwright共通ハーネスはHTTP 4xx／5xxのURLも起動エラーへ記録し、再発時に対象リソースを特定できるようにする。

## 監査基盤の改善
- モバイル幅でCCFOLIAプレビュー切替タブ、記録の並び順、抽出パック選択、ボタン、送信ボタン、フォーム入力欄の実タップ領域を40px以上へ補正。最終スタイルは外部コンポーネントCSS読み込み後に適用し、CSSカスケードによる上書き漏れを防ぐ。
- タップ領域の診断では、対象セレクターだけでなく全ボタン・リンク・入力・summaryの小領域もタグ・クラス・実寸で記録。ネイティブのチェックボックス／ラジオや意図的な小型装飾を一律に拡大せず、役割別に判断する。
- UI撮影中に可視ダイアログ／シートがある場合は、その表示状態でaxeを実行し、対象画面・viewport・違反ノードをmanifestに保存。別工程でも主要12セクションのaxe詳細をJSON成果物へ保存する。

- スクリーンショット／操作監査に画面切替後のスクロール位置テストを追加。
- アカウント編集・削除、人格お気に入り、残高ナビゲーションを40pxタップ領域監査へ追加。
- 既知セレクターに依存する監査だけでは新規UIを見落とすため、画面内に実際に存在するボタン・リンク・入力・summaryもDOM診断データへ記録するよう変更。40px未満を一律に失敗扱いせず、タグ・クラス・画面内座標で分類できるようにした。
- 利用者向けアクセスカウンター撤去後も残っていた、監査ハーネス内の旧カウンターAPIモックを削除。

### 追加axe診断で検出した問題と修正（PR #493内）

最初の26ビュー詳細診断では、合計24ノード（重大・深刻）が見つかった。内訳は、スキル未登録時の旧deckスクロール領域1件、罪属性の赤／紫チップのコントラスト不足12件、精神の「混乱」タグのコントラスト不足11件。いずれも診断上の画面・DOMノードまで確認した。

**修正:**
- スキル未登録状態を、編集可能時にはキーボードでも実行できる実ボタンへ変更。旧5列横スクロールを解除し、単一列の空状態にする。閲覧モードはネイティブのdisabledボタンにして、操作不可を視覚・支援技術双方へ伝える。
- 罪属性チップおよびE.G.O資源カウントの赤・紫文字を明るく調整。罪属性自体の色は背景・枠に残し、色による識別性は維持する。
- 精神の「混乱」タグ文字を明るく調整し、背景とのコントラストを確保する。
- 26ビュー詳細axe診断でcritical／serious違反をCIゲート化。診断失敗時もJSONをartifactへ保存して、問題箇所を確認できるようにする。
- 画面全体のaxeとダイアログ／シート状態のaxeは別々に集計する。従来の画面全体の違反ノード数と誤解される集計名を廃止し、後者をoverlay専用と明示する。

### 修正後のコントラスト目標
- 憤怒チップ：4.38:1 → **6.53:1**
- 傲慢チップ：3.45:1 → **8.72:1**
- 混乱タグ：3.41:1 → **6.01:1**

色値は既存の暗色背景で測定したCSS前景色／背景色の組合せに基づく。最終的な合否はCI上のChromium axe再実行で確認する。

## 良好だった点・維持事項

- 主要4幅の撮影対象でドキュメント横はみ出し・重大なレイアウト警告を検出しなかった。
- SINNER SELECTのアカウント一覧・編集カードはスクロール領域が確保され、カードと操作ボタンの重なりは見られなかった。
- ショップはカテゴリ選択ハブから各分類へ移動でき、戻る導線を保持。人格カードはビルド画面のカード表現と統一されている。
- ビルド9タブはスマートフォンで複数行グリッドになり、タブが横方向に押し潰されない。
- 設定の開閉項目、取り込み先選択、共有方法、保存データの範囲確認、検索、ホームのランチャーなどを撮影・操作確認した。
- 取り込み・共有・保存の確認画面は使い捨てQAデータで開閉し、実データへの適用や外部公開はしていない。

## 残課題と監査の限界

1. **アクセシビリティ:** 全画面axeは26ビューを1440x900で検査し、critical／serious違反をCIゲートにする。ダイアログ／シートaxeは撮影時に可視となった125状態を4 viewportで検査する。全メニュー・ポップオーバー・バリデーション状態の全組合せ、フォーカストラップ、読み上げ順、Escape復帰、スクリーンリーダー実機での確認は別途必要。
2. **画面幅・拡大:** 320pxの狭幅でも主要操作シナリオを巡回した。ただし200%／400%の実ブラウザズーム操作と、その状態での全フォーム内容の再確認は別途必要。
3. **ブラウザ・実機:** Chromium中心。実機iOS Safari／Android Chrome、Firefox、Safariのフォント・スクロール・タッチイベントは検証していない。
4. **操作領域の分類:** 全操作要素の小領域を診断ログに残すようにしたが、すべてを40px以上へ機械的に拡大するのは適切でない。文字入力・タグ・密集した表の操作などは周辺余白や誤操作リスクを見ながら分類し、修正対象を追加する。

以上から、主要UI経路のレイアウト／操作回帰は良好だが、「全ブラウザ・全アクセシビリティ条件で不具合ゼロ」とは判定しない。
